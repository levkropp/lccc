Vectorization coverage for loop_patterns benchmark (map + wider reductions).

Current state (verified):
- sum_array (i32 reduction over i32 array) vectorizes only 2-wide via sxtl;
  GCC does 4-wide (sxtl + sxtl2, two vector accumulators). ~1.86x vs GCC.
- dot_product (i32*i32 -> i64 accumulate) is NOT vectorized; GCC uses smlal/smlal2.
- scale_add (map pattern: out[i] = a[i]*k + b[i]) is NOT vectorized.
- Conditional reductions (sum of elements meeting a predicate) were deliberately
  rejected as unsafe earlier (select semantics / FP exception concerns). Only
  revisit with a fresh safety analysis: integer-only, no FP, prove the select
  has no side effects and the identity element is correct for skipped lanes.

4. Conditional reduction: integer-only, side-effect-free select, correct identity.
